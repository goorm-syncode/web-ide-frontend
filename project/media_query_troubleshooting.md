# 📱 미디어 쿼리 문제해결 및 반응형 레이아웃 가이드

오늘 작업 중 발생한 미디어 쿼리 관련 문제와 이를 해결하며 도출된 최적의 대응 방안을 정리한 문서입니다. 향후 유사한 레이아웃 이슈 발생 시 이 가이드를 우선적으로 참조하세요.

---

## 1. 🔍 발생했던 주요 문제 (Problem)

1. **모바일 레이아웃 잘림 현상**:
   - 화면 너비를 줄여도 오른쪽 콘텐츠가 잘리거나, 데스크탑용 고정 너비가 유지되어 가로 스크롤이 발생함.
   - 미디어 쿼리를 작성했음에도 불구하고 모바일 전용 스타일이 화면에 반영되지 않음.

2. **레이아웃 고착화 (Stiffness)**:
   - 카드의 높이가 고정되어 해상도에 따라 부자연스럽게 보이거나, 내용이 많아질 때 레이아웃이 깨지는 현상.

3. **Specificity(명시도) 충돌**:
   - 스타일 우선순위를 잡기 위해 `!important`를 남발하게 되어 코드가 복잡해지고 유지보수가 어려워짐.

---

## 2. 💡 문제의 근본 원인 (Root Cause)

1. **CSS 선언 순서 역전 (Cascading Issue)**:
   - CSS는 아래쪽에 선언될수록 우선순위가 높습니다. 기본 스타일을 미디어 쿼리**보다 아래에** 선언하면, 화면이 아무리 작아져도 아래에 있는 기본 스타일이 모바일용 미디어 쿼리를 덮어버립니다.

2. **고정 수치(Hardcoded px) 사용**:
   - `grid-template-rows: 220px`와 같이 고정 수치를 그리드에 사용하면 내용물이나 브라우저 배율 변화에 유동적으로 대응할 수 없습니다.

3. **최소 너비(min-width)의 장벽**:
   - 데스크탑에서 레이아웃을 유지하기 위해 준 `min-width: 900px` 같은 속성이 모바일에서도 그대로 살아있어 화면이 찌그러지는 것을 방해함.

---

## 3. ✅ 해결책 및 적용 내용 (Solutions)

1. **CSS 구조 재정렬**:
   - **기본 스타일**을 상단에, **미디어 쿼리**를 파일 최하단에 배치하여 브라우저가 화면 크기에 맞춰 자연스럽게 스타일을 오버라이드하게 함.

2. **유연한 단위 활용**:
   - 고정 높이 대신 `auto` 또는 `min-content`를 사용.
   - 그리드 열 너비에 `1fr`을 사용하여 화면 너비에 맞춰 카드가 자동으로 커지고 작아지도록 개선.

3. **모바일 방어 로직**:
   - 모바일 분기점(1024px 이하)에서 `min-width: 0`을 명시하여 데스크탑용 최소 너비 제약을 명확히 해제함.

---

## 4. 🤖 Antigravity의 의견 (Best Practices)

다음에 반응형 기능을 구현할 때 다음 세 가지 원칙을 지키면 오늘과 같은 삽질(?)을 획기적으로 줄일 수 있습니다.

1. **"Mobile-First"로 생각하기**:
   - 복잡한 데스크탑 화면을 먼저 만들고 깎아내기보다는, 가장 단순한 모바일 화면을 기본으로 작성하고 큰 화면용 스타일을 추가하는 것이 더 견고한 코드를 만듭니다.

2. **`!important`는 최후의 수단으로**:
   - `!important`를 쓰는 대신 셀렉터를 더 구체적으로 쓰거나(`div .title` 대신 `.parent .title`), CSS 선언 순서를 다시 확인하세요. 깨끗한 CSS가 성능과 유지보수에 훨씬 유리합니다.

3. **디바이스가 아닌 '비율'로 설계하기**:
   - 단순히 iPhone, iPad 크기에 맞추려 하지 말고, **"언제 화면이 어색해지는가(Breakpoints)"**를 기준으로 디자인을 유연하게 조정하세요.
