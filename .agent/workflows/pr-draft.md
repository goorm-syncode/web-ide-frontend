# PR Draft 생성

현재 작업 내용을 기반으로 GitHub PR 본문 초안을 작성해주세요.

---

## 사전 확인

1. 현재 브랜치가 `main` 또는 `develop`인지 확인합니다
2. 해당 브랜치라면 PR 본문 생성을 중단하고 경고를 출력합니다
3. 그 외 브랜치라면 정상적으로 진행합니다

---

## 중단 조건

아래 경우에는 PR 본문을 작성하지 말고 이유를 먼저 설명합니다

- 현재 브랜치가 `main` 또는 `develop`인 경우
- 변경사항이 거의 없거나 PR로 올릴 내용이 없는 경우

---

## 입력 정보

- 현재 브랜치: 자동 확인
- 대상 브랜치: `develop`
- 작업 내용 요약: 사용자가 선택적으로 추가할 수 있음
- 추가 설명 또는 보정 지시가 있으면 반영하고, 없으면 현재 변경사항만 기준으로 작성합니다

---

## 요구사항

반드시 저장소의 PR 템플릿 구조를 그대로 따르세요 (체크리스트 포함)

다음 섹션을 모두 작성해주세요:

- 작업 내용
- 변경 파일
- 테스트 방법
- 스크린샷
- 체크리스트

---

## 입력 해석 규칙

- 사용자의 추가 입력은 순서와 관계없이 해석합니다
- 입력에서 스크린샷 관련 의도를 먼저 파악합니다
- 남은 텍스트는 보정 지시로 해석합니다

스크린샷 의도 해석:

- 포함 의미 → include
- 제외 의미 → exclude
- 명시 없음 → auto

판단 기준:

- 키워드(포함/추가/넣어/필요 → include, 제외/삭제/빼/불필요 → exclude)를 참고하되  
  자연어 문맥을 함께 해석하여 의도를 판단합니다
- 표현(스크린샷, 스샷, 캡처, 이미지 등)은 자유롭게 허용합니다
- 입력 위치(앞/중간/뒤)는 관계없이 동일하게 처리합니다
- 사용자 의도는 자동 판단보다 항상 우선합니다
- 의도가 애매한 경우 auto로 처리합니다

---

## 스크린샷 판단 규칙

UI 변경으로 간주:

- 화면에 보이는 컴포넌트 구조 변경
- Button, Input, Card, MessageBox 등의 스타일 변경
- layout, spacing, typography, color, border, radius, shadow 변경
- 새로운 화면 또는 Dev 페이지 추가
- 에러 메시지, helperText, 상태 UI 변경

UI 변경이 아닌 경우:

- 문서 파일만 수정
- workflow, template, instructions 등 설정 변경
- 로직만 변경되고 UI 표시 변화 없음
- 포맷 정리 및 리팩토링

출력 규칙:

- auto → UI 변경 여부 기준 판단
- include → 무조건 포함
- exclude → 무조건 제외

출력 형태:

- UI 변경 있음 (auto):
  - 📸 스크린샷 첨부 필요 (첨부 후 이 문구 삭제)

- UI 변경 없음:
  - 해당 사항 없음

- 사용자 override 포함:
  - 📸 스크린샷 첨부 필요 (사용자 요청, 첨부 후 이 문구 삭제)

- 사용자 override 제외:
  - 해당 사항 없음 (사용자 요청)

---

## 출력 형식

PR 초안은 다음 두 가지 형태로 모두 제공해야 합니다:

1. **Preview**: PR 템플릿에 맞게 작성된 본문 (가독성을 위한 일반 출력)
2. **Markdown Code Block**: 복사 붙여넣기가 가능하도록 전체 본문을 포함한 `markdown` 코드 블록

## 작성 규칙

- 현재 브랜치 기준의 핵심 변경사항만 요약합니다
- 변경 파일은 중요한 파일만 간단히 나열합니다
- 테스트 방법은 아래 형식을 반드시 따릅니다:

```md
- Dev 경로: 해당 사항 없음 (문서/설정 변경) 또는 /dev/...
- 확인 내용:
```
