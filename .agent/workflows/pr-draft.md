# PR Draft 생성

현재 작업 내용을 기반으로 GitHub PR 본문 초안을 작성합니다. 이 워크플로우는 프로젝트의 PR 템플릿(`.github/pull_request_template.md`)을 엄격히 준수하며 일관된 드래프트를 생성하는 것을 목표로 합니다.

---

## 사전 확인 및 변경사항 분석

PR 본문을 작성하기 전에 반드시 다음 단계를 수행하여 **현재 작업 브랜치의 순수 변경사항**만 추출해야 합니다.

1. **현재 브랜치 확인**: `main` 또는 `develop`인 경우 PR 생성을 중단하고 경고를 출력합니다.
2. **베이스 브랜치 최신화**: `git fetch origin`을 실행하여 최신 `develop` 상태를 가져옵니다.
3. **변경 파일 추출**: `git diff origin/develop...HEAD --name-only` (Triple-dot diff) 명령어를 사용하여, **현재 브랜치가 `develop`에서 분기된 시점 이후로 추가된 고유한 변경 내역**만 확인합니다.
4. **커밋 메시지 분석**: `git log origin/develop..HEAD --oneline` 명령어로 현재 브랜치에 포함된 커밋들을 분석하여 작업 의도를 정확히 파악합니다.

---

## 중단 조건

아래 경우에는 PR 본문을 작성하지 말고 이유를 먼저 설명합니다:

- 현재 브랜치가 `main` 또는 `develop`인 경우
- 변경사항이 거의 없거나 PR로 올릴 내용이 없는 경우

---

## 작성 규칙 (필수 준수)

### 1. PR 제목 규격
- 형식: `[태그] 작업내용 요약`
- 태그 종류: `[feat]`, `[fix]`, `[style]`, `[refactor]`, `[chore]`
- **주의**: 제목에는 절대 이모지를 사용하지 않습니다. (예: `[feat] 로그인 UI 구현`)

### 2. 템플릿 준수 및 정제
- `.github/pull_request_template.md`의 모든 섹션 제목과 아이콘을 **그대로** 유지합니다.
- 작성 시 템플릿의 주석(`<!-- ... -->`)은 모두 **삭제**하여 깔끔한 결과물을 만듭니다.
- 사용되지 않는 섹션이라도 제목은 그대로 유지하며, 내용은 `해당 사항 없음`으로 기재합니다.

### 3. 체크리스트 동작
- **절대 금지**: AI는 체크리스트 항목을 임의로 체크(`[x]`)하지 않습니다.
- 모든 항목은 템플릿에 있는 그대로 `[ ]` 상태로 출력해야 합니다.

### 4. UI 작업 여부 판단 및 분기
변경 파일 중 `.jsx`, `.css`, `styles/` 폴더 내 파일 등이 포함된 경우 **UI 작업**으로 간주합니다.

- **UI 작업인 경우**:
  - **테스트 방법**: `Dev 경로`에 실제 확인할 수 있는 `/dev/...` 경로를 기입합니다.
  - **스크린샷**: `📸 스크린샷 첨부 필요 (첨부 후 이 문구 삭제)` 문구를 출력합니다.
- **UI 작업이 아닌 경우**:
  - **테스트 방법**: `Dev 경로`에 `해당 사항 없음 (로직 변경)`으로 기입합니다.
  - **스크린샷**: `해당 사항 없음`으로 기입합니다.

---

## 출력 형식

PR 초안은 다음 두 가지 형태로 모두 제공해야 합니다:

1. **Preview**: PR 템플릿에 맞게 작성된 본문 (가독성을 위한 일반 출력)
2. **Markdown Code Block**: 복사 붙여넣기가 가능하도록 전체 본문을 포함한 `markdown` 코드 블록 (제목 포함)

---

## 입력 정보 가이드

안티그래비티(Antigravity)는 사용자의 추가 입력(스크린샷 포함 여부 등)이 있는 경우 이를 최우선으로 반영하되, 명시적인 지시가 없는 경우 위의 **UI 작업 여부 판단 규칙**에 따라 자동으로 내용을 채웁니다.
