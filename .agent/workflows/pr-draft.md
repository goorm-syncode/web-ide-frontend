# PR Draft 생성

현재 작업 내용을 기반으로 GitHub PR 본문 초안을 작성해주세요.

## 사전 확인

1. 현재 브랜치가 `main` 또는 `develop`인지 확인합니다.
2. 해당 브랜치라면 PR 본문 생성을 중단하고 경고를 출력합니다.
3. 그 외 브랜치라면 정상적으로 진행합니다.

## 중단 조건

아래 경우에는 PR 본문을 작성하지 말고 이유를 먼저 설명합니다.

- 현재 브랜치가 `main` 또는 `develop`인 경우
- 변경사항이 거의 없거나 PR로 올릴 내용이 없는 경우

## 입력 정보

- 현재 브랜치: 자동 확인
- 대상 브랜치: `develop`
- 작업 내용 요약: 사용자가 선택적으로 추가할 수 있음
- 추가 설명이 있으면 반영하고, 없으면 현재 변경사항만 기준으로 작성함

## 요구사항

반드시 저장소의 PR 템플릿 형식을 따르세요.

다음 섹션만 작성해주세요:

- 작업 내용
- 변경 파일
- 테스트 방법
- 스크린샷 (선택)

체크리스트 섹션은 절대 출력하지 마세요.

## 작성 규칙

- 현재 브랜치 기준의 핵심 변경사항만 요약합니다
- 변경 파일은 중요한 파일만 간단히 나열합니다
- 테스트 방법은 실제 확인 가능한 형태로 작성합니다
- UI 변경이 있으면 스크린샷 필요 여부를 간단히 표시합니다
- 체크리스트는 포함하지 않습니다

## 금지 사항

- `file://`, `cci://`, 로컬 경로, 내부 링크 사용 금지
- 이전 작업 내용이나 관련 없는 변경사항 포함 금지
- 포맷 변경만 있는 경우 이를 주요 변경으로 작성하지 않기
- 불필요하게 길게 작성하지 않기

## 출력 형식 (중요)

- 설명 없이 결과만 출력합니다
- 결과는 GitHub PR 본문에 바로 붙여넣을 수 있는 마크다운 초안 형식이어야 합니다
- 반드시 하나의 코드블록으로 감싸서 제공합니다
- 바깥 코드블록은 백틱 4개를 사용합니다
- 내부에 코드블록이 필요한 경우 일반 백틱 3개를 사용합니다

## 출력 방식

조건을 만족하는 경우:

- PR 본문 초안만 출력합니다

조건을 만족하지 않는 경우:

- 실행 불가 이유
- 필요한 조치
